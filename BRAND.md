# Ankui Brand Guidelines

These guidelines keep the public Ankui name clear and avoid implying features or services that are not in this repository.

This is a project branding policy, not a claim that `Ankui` is a registered trademark and not a restriction on the MIT code license. The MIT license applies to code and documentation in this repository.

## Name

Use `Ankui` for the project name. Use lowercase `ankui` only for the CLI command, npm package name, repository slug, or code identifiers.

## Accurate description

Describe Ankui as a local, single-device, local-first scanner/UI for AI coding tool configuration.

Do not describe this repository as a hosted control plane, centralized org inventory, endpoint fleet management product, remote policy management system, centralized audit/evidence retention system, SSO product, SIEM integration, runtime enforcement engine, telemetry service, or customer-data platform.

## Community use

You may use the Ankui name to refer to this repository, discuss the project, write tutorials, package integrations, or identify compatibility with the `ankui` CLI.

Do not use the Ankui name or any project artwork in a way that implies endorsement, official status, security certification, commercial availability, hosted service operation, pricing, roadmap commitments, or proprietary access.

## Forks and derivatives

Forks are welcome under the MIT license. If you publish a fork, plugin, package, or service, make it clear that it is not the official Ankui project unless maintainers have explicitly approved that use.

Modified distributions should use a clearly differentiated name and visual identity. Use a distinct package name for redistributed forks. Do not publish a modified package in a way that could be confused with the official `ankui` package.

## Safety wording

When using Ankui safety claims, keep them tied to the current repository behavior:

```text
Scans are read-only. The only optional mutation is a user-confirmed, reversible skill enable/disable action.
```

Do not weaken this claim unless the code no longer supports it, and do not expand it into promises about runtime blocking, fleet enforcement, centralized retention, or hosted administration.
